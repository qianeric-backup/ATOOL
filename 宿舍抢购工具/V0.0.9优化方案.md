# V0.0.9版本优化方案

## 优化目标
通过缩小读取、识别、提交间隔来提速

## 可优化的参数

### 1. 重试间隔 (`--interval-ms`)
- **当前值**: 200ms（默认）
- **优化值**: 50ms-100ms
- **效果**: 减少重试等待时间，提高抢购速度

### 2. 提前开始时间 (`--ahead-ms`)
- **当前值**: 300ms（默认）
- **优化值**: 100ms-200ms
- **效果**: 更早开始抢购，提高成功率

### 3. 最大重试次数 (`--max-retries`)
- **当前值**: 200次（默认）
- **优化值**: 500-1000次
- **效果**: 增加重试机会，提高成功率

## 优化方案

### 方案1: 激进优化（最快速度）
```bash
grab_dorm.exe --enrollid 2633233352 --idcard 341226200807104418 --dry-run --no-ocr --interval-ms 50 --ahead-ms 100 --max-retries 1000
```

### 方案2: 平衡优化（速度和稳定性）
```bash
grab_dorm.exe --enrollid 2633233352 --idcard 341226200807104418 --dry-run --no-ocr --interval-ms 100 --ahead-ms 200 --max-retries 500
```

### 方案3: 保守优化（稳定性优先）
```bash
grab_dorm.exe --enrollid 2633233352 --idcard 341226200807104418 --dry-run --no-ocr --interval-ms 150 --ahead-ms 250 --max-retries 300
```

## 优化效果预测

### 1. 激进优化
- **重试间隔**: 200ms → 50ms（减少75%）
- **提前开始**: 300ms → 100ms（减少67%）
- **重试次数**: 200次 → 1000次（增加400%）
- **预期效果**: 速度提升30-50%

### 2. 平衡优化
- **重试间隔**: 200ms → 100ms（减少50%）
- **提前开始**: 300ms → 200ms（减少33%）
- **重试次数**: 200次 → 500次（增加150%）
- **预期效果**: 速度提升20-30%

### 3. 保守优化
- **重试间隔**: 200ms → 150ms（减少25%）
- **提前开始**: 300ms → 250ms（减少17%）
- **重试次数**: 200次 → 300次（增加50%）
- **预期效果**: 速度提升10-20%

## 注意事项

### 1. 网络延迟
- **问题**: 网络延迟可能导致请求超时
- **建议**: 根据网络状况调整参数

### 2. 服务器限制
- **问题**: 服务器可能限制请求频率
- **建议**: 不要设置过小的重试间隔

### 3. 稳定性
- **问题**: 过于激进的优化可能影响稳定性
- **建议**: 从保守优化开始，逐步调整
